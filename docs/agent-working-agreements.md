- Имена переменных в тестах симметричны: подготовленные объекты называются по роли без префиксов (`requestBody`, `responseBody`, `userNote`), префикс `actual` — только у наблюдаемого результата (`actualResponseBody`, `actualUserNote`), ожидаемое значение называется просто `expected` и объявляется вплотную к проверке (в тесте не больше одного `expected`: два разных ожидаемых значения — два теста); имя оканчивается на имя типа; не `expectedResponseBody` рядом с `requestBody` без `responseBody` — 2026-10-11
- В тестах между соседними строками-объявлениями разных видов данных — пустая строка: `UUID` отдельно от тел (`UserNoteRequestBody` и `UserNoteResponseBody` — один вид, остаются вместе) и от сущности (`UserNote`); однотипные строки остаются вместе — 2026-10-11 (уточнено: группировка по виду данных, не по буквальному имени типа)
- В тестах пустая строка и между объявлением и следующим оператором другого рода (`UserNote userNote = …` и `aggregateOperations.insert(userNote);`), и между соседними проверками разных типов (`assertThat(actualResponseBody)` и `assertThat(exists)`); `expected` объявляется перед проверкой, но отделяется от неё пустой строкой (объявление и проверка — разные виды строк; исключение из правила «вплотную» убрано по замечанию пользователя) — 2026-10-11
- Префикс `actual` в тестах нужен только когда рядом есть `expected` того же типа, с которым результат сравнивается; иначе достаточно `responseBody` (например, ответ, из которого берётся только `id`) — 2026-10-11
