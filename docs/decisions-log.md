### Архитектура

- **Convention plugins в `build-logic/convention/`** (included build, не `buildSrc/`) — инкрементальность, `./gradlew clean build` одной командой; id namespaced `com.example.{name}`; каталог плоский, id — из имени файла, группировка — алфавитом (слово-маркер — префикс)
- Gradle — Kotlin DSL, код — Java; в precompiled script plugins — `libs.findVersion("key").get().requiredVersion`, не typed-аксессоры каталога
- `spring-boot-starter`/`-test` — в `com.example.spring-boot` (baseline любого Boot-модуля); bootable-ось (`org.springframework.boot`) ортогональна BOM-цепочке
- Плагин `idea` удалён (deprecated)
- **Именование convention-плагинов для sort-by-name-группировки** (2026-07-23) — слово-маркер как суффикс не группирует (`{vendor}-database` → `spring-boot-database-{vendor}`); приватные фрагменты одной композиции — общий префикс (`codequality-*`); неточные имена технологий — к имени стартера Boot 4 (`oauth2-*` → `security-oauth2-*`, `client-web`/`-rest` → `client-webclient`/`-restclient`). Отклонено: объединять имена `docker-compose`/`testcontainers` — разные концерны (dev-время против тестов); **группировка по имени — только для действительно родственных технологий, не для применяемого вместе сегодня**
- Type-safe project accessors (`TYPESAFE_PROJECT_ACCESSORS`) — были включены; с 2026-09-05 флаг убран по просьбе пользователя, зависимости — `project(":...")`
- `api` — только когда тип в публичной сигнатуре модуля, иначе `implementation`
- Hexagonal (эпоха `note/`): `domain/` без JPA/Mongo/Spring; адаптеры зависят от `contract*` и явно от `domain`
- **Один контроллер/контракт/адаптер на сущность, не на операцию** (2026-07-08)
- `service/` — только при координации нескольких портов; `existsById` в контракте — валидно; `add` ≠ `replace` (JPA `save(null id)`/`save(id)`, Mongo `insert()`/`save()`)
- Старый `user-note/`: суррогатный `UUID id` + unique (`userId`, `noteId`) во всех технологиях — снимает отсутствие `@EmbeddedId` в R2DBC; unique: JPA — `@Table(uniqueConstraints)`, Mongo — `@CompoundIndex(unique=true)`, JDBC/R2DBC — только схемой
- Схема JDBC/R2DBC — `schema.sql` (2026-07-14), Flyway/Liquibase не рассматривались; enum маппится в строку из коробки
- `data-jdbc` — Spring Data JDBC (`ListCrudRepository`), решение «сырой JDBC» отменено 2026-07-14
- **Трёхуровневая иерархия портов** (2026-07-13): `{Entity}Interface[Reactive]` → `{Entity}ServiceInterface[Reactive]` → `{Entity}ControllerInterface[Reactive]`; первоначально через ковариантный `Object`
- **Трёхуровневая иерархия портов: `Object`-ковариантность → generic-параметризация** (2026-08-08) — `Object` — вырожденный контракт (наследование ради синтаксиса); заменён на `{Entity}Interface<B, S, L>`/`<B, S, L, V>` (reactive, `V` — тип удаления); реализации не менялись. Тем же днём **`L` признан неустранимым свободным параметром** — инвариантность generics (`Box<List<X>>` ≠ `Box<Iterable<X>>`, проверено `javac`), `Flux` не `Iterable` (исходники reactor-core); решение — `<B, S>` для однородных методов, `findAll`/entity-finder'ы — конкретными типами в каждом интерфейсе (прецедент `findByEmail`). Отклонены: HKT-эмуляция (тяжело), отказ от `ResponseEntity` (жёсткое требование), GoF Adapter без общего предка (теряет проверку компилятором), кодогенерация (исключена пользователем). Урок — чек-лист «стандартный паттерн прежде локального рецепта» (CLAUDE.md → «Правила»)
- Старый `user-note/` — операции по суррогатному и составному ключу раздельно; `findByUserId`/`findByNoteId` бросают свои исключения (изоляция сервисов)
- **PUT (`replace`) ≠ PATCH (`merge`)** — `merge`: `null` = «не менять»; оба — `NotFoundException` при отсутствии
- Несколько `@GetMapping` на одном пути — атрибут `params`, иначе `Ambiguous mapping`
- Reactive `findBy*` бросают `NotFoundException`, не пустой `Mono` (2026-07-13); `findAll` — `ResponseEntity<Flux<X>>`
- **Группировка модулей по слою в подпапку** (2026-08-01) — `{service}/{layer}/{module}/`, project path плоский через `projectDir`; неактуально с 2026-08-29 (`user-note/` плоский)
- `contextLoads()` vendor-скелетов на embedded H2 через `testRuntimeOnly` (2026-08-18) — smoke-тесту не нужен реальный вендор; снято 2026-09-05 реальными Testcontainers
- **Тесты — на уровне application/bootable-модулей** (2026-08-18) — sociable/classicist (реальный контекст, без Mockito); модуль-реализация владеет механизмом, не целью — поведение принимает тот, кто собирает систему (аналогия acceptance testing, симметрично DI); семантическое дублирование сценария — shared-модуль с абстрактным тестом + тонкие подклассы; структурное (`@SpringBootApplication` на лист) — неустранимо, принято
- **Вехи переписывания 2026-08-14→2026-09-24**: 08-14 удалены `auth`/`config`/`gateway`/`registry`; 08-29 удалены гексагональный слой `user-note/` и `note/`/`user/`; 08-31 модули не сворачивать, абстракция — по ходу TDD; 09-05 application-driver → application-vendor; 09-06 `application-core` испробован (отменён 09-13), `spring-boot-bootable`, PMD/SpotBugs; 09-13 `libs.versions.toml` по алфавиту; 09-21 центральный вопрос, корневое дерево, `controller-*`/`data-*`, 4 пробела; 09-24 `contract`-плагины, `codequality` воссоздан, `java-library` удалён, `java` → `base`. Подробно — «Хронология переписывания `user-note/`» ниже

### HTTP / Ошибки

- Ручной, без MapStruct, ответственность адаптера; `Pageable`/`Page`/`Specification` в контрактах не использовать (утечка инфраструктуры)

### Convention plugins — принцип именования и структура

- Id — по технологии, не по модулю/слою (исключения — CLAUDE.md → «Правила» → «Имя convention-плагина»); две оси — BOM-цепочка (один родитель) и bootable (`org.springframework.boot`); актуальный граф — `docs/convention-plugins-graph.md`
- `codequality-*` — фрагменты: checkstyle, jspecify (`id("java")` + `implementation`, не `java-library` — 2026-07-15), nullaway (+ `net.ltgt.errorprone`), jacoco, jacoco-report-aggregation; позже spotless, pmd, spotbugs
- **Диамант `spring-cloud-application`** — 2026-07-15 устранён копией BOM-импорта, тем же днём пользователь восстановил (два родителя), **2026-08-01 устранён окончательно** прямым `id("org.springframework.boot")` — стало возможно после выноса actuator (`spring-boot-application` стал чистым алиасом)
- **Технологическая и вендорная ось адаптеров** (2026-07-23) — технология адаптера (jpa/jdbc/r2dbc/mongodb/mongodb-reactive) — отдельный composition-root модуль, не `@Profile`: одна repository-технология на classpath → autoconfiguration работает сама, новая технология — только новые файлы. Вендор тогда был профилем (`runtimeOnly`-драйверы + `application-{vendor}.properties`); без профиля и JDBC, и R2DBC встают на embedded H2 (проверено; предположение «у R2DBC нет embedded» было ошибкой). Mongo без embedded-аналога — Testcontainers (`org.testcontainers.mongodb.MongoDBContainer`, один контейнер на sync и reactive) + `spring-boot-docker-compose`; тем же днём сняты ради симметрии и **возвращены симметрично** — PostgreSQL/MySQL доведены до того же покрытия
- **`MySQLContainer` требует JDBC-драйвер** (wait-strategy от `JdbcDatabaseContainer`), `PostgreSQLContainer` — нет (log-based) → `testRuntimeOnly(mysql-connector-j)` в `spring-boot-testcontainers-mysql`; `testcontainers-r2dbc` необходим (без него `ClassNotFoundException` при `@ServiceConnection` → `ConnectionFactory`)
- **Вендор БД — граница Gradle-модуля, не рантайм-профиль** (2026-07-24) — профиль выбирает бин, но не убирает драйверы из `bootJar` (driver bloat); один composition root на вендор; порядок имени пересмотрен тем же днём на `{vendor}-{tech}` (`application-h2-jpa`); `spring-boot-database-{vendor}-r2dbc`; проверено `dependencies --configuration runtimeClasspath` — в модуле только свой драйвер. 2026-08-19 для `user-note/` был возврат к объединённому модулю (driver bloat принят), отменён 2026-09-05 моделью application-vendor
- **Атомизация базовых плагинов** (2026-08-01) — `base` → `java`, `library` → `java-library` (id = имя ядрового плагина; голый `com.example` отклонён — сортируется не первым); агрегатор `codequality` убран (один потребитель); `spring-boot-validation` — атомарный, только где Bean Validation реально срабатывает; `reactor` → `project-reactor` (по императиву пользователя); `spring-boot-actuator` — атомарный, явный `id` на каждом bootable-листе (выбор пользователя: атомарность важнее числа правок). Позже: 2026-09-24 `java` → `base` обратно, `codequality` воссоздан (8 фрагментов), `java-library` удалён
- **Урок `developmentOnly`** (2026-08-01) — `id("org.springframework.boot")` в `spring-boot-docker-compose` не дубликат: typed-аксессор `developmentOnly` генерируется только от плагинов, применённых в этом же файле
- Gateway-плагины → `spring-cloud-gateway-server-webflux`/`-webmvc` (имя артефакта); `spring-cloud-*`-server-плагины — родитель `spring-cloud`, bootable — явной композицией на листе, без исключений
- **Правило «диаманты — всегда устранять»** (2026-08-01) — пользователь дважды принимал диамант ради экономии кода и оба раза откатывал; закреплены три постоянных правила: атомарные плагины, 0 диамантов даже ценой copy-paste, `.gitattributes` = шаблон Initializr. **Урок**: широкий `git checkout` отката стёр `spring-boot-actuator` с 37 листов при зелёном `clean check` (исправлено 2026-08-02) — отсюда правило сверки числа применений грепом
- **Spring Batch** (2026-08-15) — `spring-boot-batch`/`-batch-jdbc`/`-batch-data-mongodb`: три независимых id Initializr — три атомарных плагина, 0 применений

Голого `mongodb-reactive` у Initializr нет

### Синхронизация версий

- Единый источник Spring-версий — `gradle/libs.versions.toml`; `build-logic` подключает тот же каталог отдельно
- Boot BOM — `SpringBootPlugin.BOM_COORDINATES`; Spring Cloud BOM — координаты вручную (второй источник неизбежен только здесь)

### Стиль кода

- Bean Validation подключена, аннотации не расставлены — не реализовывать без запроса
- `@Service` на адаптерах, `@Repository` на Spring Data-интерфейсах (2026-07-14)
- Промежуточная переменная перед `return`
- 2026-07-13…08-16 — стиль Spring (`SpringChecks`, 10 персональных правил, свои группы импортов, `.editorconfig`, Spotless с автофиксом на `compileJava`, `lineEndings=PRESERVE`); **с 2026-09-04 заменено Google Checks + `googleJavaFormat().aosp()`** (CLAUDE.md → «Правила» → «Отступы», «Ноль ошибок и предупреждений»).
