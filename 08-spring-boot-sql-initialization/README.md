# 08 · Spring Boot SQL Initialization

Level: junior. Status: not started.

## Change

The schema is created by Spring Boot SQL initialization from `schema.sql` instead of being generated by Hibernate, and Hibernate only validates the entities against it: the application fails at startup when an entity does not match the schema.

## Why

Since 01 Hibernate generates the schema from the entities, and with the users of 06 and 07 the schema has started to grow: it is never written down, an update never removes or renames anything, so the database drifts away from the code, and nothing reports the difference.

## Tools

- Spring Boot SQL initialization with `schema.sql`; `spring.sql.init.mode` defaults to `embedded`, so it is set to `always` for the script to run on PostgreSQL as well as on the embedded H2 of the tests.
- `spring.jpa.hibernate.ddl-auto=validate` instead of the generation of 01; the schema generation of Hibernate and `schema.sql` must not both create the schema, and `spring.jpa.defer-datasource-initialization` decides their order where they meet.
- The defaults of these properties and the checks of the validation are confirmed against the Spring Boot and Hibernate references when the stage starts.

## Proof

- The page tests pass.
- An entity that does not match `schema.sql` stops the application at startup.
