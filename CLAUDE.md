# CLAUDE.md — notes-spring

> Последнее обновление: 2026-11-11. Новый старт проекта; прежний проект — тег `legacy-2026-11`, его документация (включая прежний `CLAUDE.md`) — `docs/archive/`.

## Цель

Освоить и продемонстрировать работодателю владение технологиями Spring: эволюция одного приложения (пользователи, заметки, доступ к заметке по ролям, уведомления) от классического монолита до распределённой конфигурируемой устойчивой системы — путь обучения от junior до senior, без экзотики. Каждый проект — законченное, протестированное, опубликованное и запущенное на сервере приложение.

## Структура репозитория

Каждый этап — предыдущий плюс одно архитектурное изменение (подробности — `README.md` этапа, обоснование — `docs/adr/0001-evolution-in-seven-stages.md`):

- `01-monolith/` — база: MVC, Data JPA, PostgreSQL, Flyway, Security + OAuth2 (Keycloak), Thymeleaf, Actuator, Testcontainers; GitHub Actions, VPS + TLS (junior)
- `02-modulith/` — границы модулей и события в процессе: Spring Modulith, журнал публикаций (middle)
- `03-event-driven/` — уведомления отдельным сервисом: Kafka, вынос событий Modulith, трассировка OpenTelemetry; GitLab CI (middle+)
- `04-microservices/` — все модули сервисами: Gateway (вход, передача токена), Config Server, Eureka, Resilience4j, Spring Cloud Contract, сага; Jenkins (senior)
- `05-kubernetes/` — платформа вместо Spring Cloud: k3s, Helm, Argo CD, автомасштабирование, Gatling (senior)
- `06-hexagonal/` — порт хранилища там, где появляется вторая реализация: Spring Data JDBC (PostgreSQL/MySQL/H2 профилем) и MongoDB, контрактный тест порта (senior)
- `07-reactive/` — второй веб-стек для сервиса уведомлений: WebFlux, реактивное хранилище, SSE; MVC и WebFlux — два приложения, выбор значением Helm (senior)
- `docs/adr/` — записи архитектурных решений, одно решение — один файл `NNNN-title.md`; принятое не переписывается, пересмотр — новая запись
- `docs/archive/` — история прежней попытки, только для справки

## Приоритеты решений

1. **Автоконфигурация Spring Boot** — стандартные стартеры и свойства; своя конфигурация бинов — только когда без неё нельзя, с названной причиной
2. **KISS и DRY** — при конфликте выбирается вариант, который не ломает автоконфигурацию и при этом избегает дублирования; если оба варианта сохраняют автоконфигурацию — тот, что проще
3. Стандартные инструменты, без экзотики: то, что встречается в типовом проекте на Spring

## Порядок работы

- Этапы делаются строго последовательно; этап начинается с коммита-копии предыдущего («copy 02 → 03»), дальше каждое изменение отдельным коммитом
- Функциональность и HTTP API фиксируются в `01` и дальше не меняются; меняется только устройство внутри
- Изменение этапа вызвано проблемой предыдущего, которую можно показать сценарием
- Готовность этапа: работает на сервере, сквозные сценарии и тесты зелёные, README заполнен, ключевые решения — в ADR; после этого этап замораживается (только исправления ошибок, безопасности и обновления зависимостей через Dependabot)
- Каждый этап — самостоятельная сборка Gradle (свои `settings.gradle.kts` и wrapper); корневой сборки и общего `build-logic` нет
- Копия кода между этапами — сознательное исключение из DRY: каждый каталог — снимок этапа; внутри этапа DRY действует
- CI — по workflow на этап с фильтром по пути; GitHub Actions везде, GitLab CI с `03`, Jenkins с `04`, Argo CD с `05`
- Версии и существование стартеров проверяются при старте этапа по Spring Initializr и docs.spring.io, не по памяти

## Правила (перенесены из прежнего проекта, на утверждение пользователя)

- Общение — на русском; код, настройки, публичные README и ADR — на английском
- Стандарты (RFC, спецификации, docs.spring.io) важнее туториалов и важнее предложения пользователя; отступление — только названное, с причиной
- Источник истины для Spring-фактов — Spring Initializr, docs.spring.io, GitHub spring-projects; не поиск Maven Central
- Архитектурные решения — варианты, рекомендация, выбор пользователя
- Ноль ошибок и предупреждений при сборке и тестах
- Коммит и пуш — только по запросу; «Зафиксируй» = синхронизировать документацию, коммит, пуш; дата — из `date`
- Стиль кода: отступ 4 пробела; локальные переменные вместо вложенных вызовов; аббревиатуры заглавными, кроме `Id`
