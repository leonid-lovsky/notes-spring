# CLAUDE.md — notes-spring

> Последнее обновление: 2026-11-11. Новый старт проекта; прежний проект — тег `legacy-2026-11`, его документация (включая прежний `CLAUDE.md`) — `docs/archive/`.

## Цель

Освоить и продемонстрировать работодателю владение выбранными технологиями: эволюция одного приложения (заметки, пользователи, доступ к заметке, уведомления) от классического монолита до распределённой конфигурируемой устойчивой системы. Каждый проект — законченное, протестированное, опубликованное и запущенное на сервере приложение; следующий строится на копии предыдущего и отличается способом связи между блоками приложения.

## Структура репозитория

- `01-monolith/` — слоистый монолит: MVC, JPA, PostgreSQL, Flyway, Security + OIDC (Keycloak)
- `02-modulith/` — Spring Modulith: модули, события внутри процесса, журнал публикаций (outbox)
- `03-event-driven/` — вынос событий в Kafka, первый отдельный сервис
- `04-microservices/` — Gateway, Config Server, Discovery, Resilience4j, сага, трассировка
- `05-kubernetes/` — та же система на k8s: Helm, Argo CD, Terraform, платформа вместо Spring Cloud
- `06-hexagonal/` — сменные «кубики»: порты и адаптеры, выбор БД, WebFlux, транспорт
- `docs/adr/` — записи архитектурных решений (ADR), одно решение — один файл
- `docs/archive/` — история прежней попытки, только для справки

## Порядок работы

- Проекты делаются строго последовательно: следующий начинается после готовности предыдущего
- Готовность проекта: работает на сервере, тесты зелёные, README с объяснением «почему так», ADR на ключевые решения
- Законченный проект замораживается — только исправления ошибок и безопасности
- Каждый проект — самостоятельная сборка Gradle (свои `settings.gradle.kts` и wrapper); корневой сборки и общего `build-logic` нет
- Копия кода между проектами — сознательное исключение из правила против дублирования: каждый каталог — снимок этапа, разница между каталогами и есть демонстрация эволюции
- CI — по workflow на проект с фильтром по пути; GitHub Actions везде, GitLab CI, Jenkins и Argo CD — на этапах, где они уместны

## Правила (перенесены из прежнего проекта, на утверждение пользователя)

- Общение — на русском; код, настройки и публичные README — на английском
- Стандарты (RFC, спецификации, docs.spring.io) важнее туториалов и важнее предложения пользователя; отступление — только названное, с причиной
- Источник истины для Spring-фактов — Spring Initializr, docs.spring.io, GitHub spring-projects; не поиск Maven Central
- Прагматизм: Spring Boot AutoConfiguration по умолчанию, своя конфигурация — только с названной причиной
- Архитектурные решения — варианты, рекомендация, выбор пользователя
- Ноль ошибок и предупреждений при сборке и тестах
- Коммит и пуш — только по запросу; «Зафиксируй» = синхронизировать документацию, коммит, пуш; дата — из `date`
- Стиль кода: отступ 4 пробела; локальные переменные вместо вложенных вызовов; аббревиатуры заглавными, кроме `Id`
